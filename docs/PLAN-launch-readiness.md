# NEON SURVIVOR — Launch Readiness Plan

Status: **draft** · Target: first *official* public launch (web + Android APK)

This plan takes NEON SURVIVOR from "already live and technically solid" to
"officially launched." The engineering is in good shape — the full `verify*.cjs`
suite is green, the game runs offline, and it's already deployed at
`neon-survivor.com` with a sideloadable APK. What's left is mostly **brand,
legal, distribution, and confirmation** work, not core code.

Priorities: **P0** = blocks an official launch · **P1** = do before/at launch ·
**P2** = fast follow, post-launch is acceptable.

---

## 0. Snapshot — what's already done

- ✅ Core game: vanilla-JS canvas auto-shooter, 3 difficulties, 3 boss archetypes, evolutions, pickups.
- ✅ Offline-first: procedural audio fallback for every genre; local leaderboard when Supabase is absent.
- ✅ Identity/leaderboard/achievements via Supabase, with **server-side run validation** (`api/verify.js`).
- ✅ i18n EN⇄HE (RTL), PWA install + maskable icons, Android APK via Capacitor CI.
- ✅ Test Mode (one-hit bosses) is dev-account-gated — players can't trigger it on the competitive board.
- ✅ 16 automated verifiers; `verify-size` guards the 28 KB per-file ceiling.

## A. Legal & privacy — **P0**

The game collects **email addresses** (Supabase auth + OTP) and stores callsigns,
scores, and achievements. A public launch — and specifically a Google Play
release — requires a published privacy policy.

- [ ] **Privacy policy page** (`/privacy`, static HTML matching the game's dark theme).
      Cover: what's collected (email, callsign, gameplay stats, device/analytics),
      why, where it's stored (Supabase), retention, deletion/contact path, third
      parties (Supabase, Vercel), and children's-data stance.
- [ ] **Terms of Service / EULA** page (`/terms`) — the repo `LICENSE` is proprietary;
      surface user-facing terms separately (acceptable use, no-cheating, account
      termination, "as-is" warranty).
- [ ] **Link both** from: the start menu (small footer links), the GRID ACCESS
      auth modal (near the email field — "By signing in you agree to …"), and the
      Play Store listing.
- [ ] **Account & data deletion path** — a user-initiated "delete my data" flow or a
      documented email request process (Play requires an account-deletion route for
      apps with accounts).
- [ ] **Play Data Safety form** — declare data collection/sharing to match the policy.
- [ ] **Cookie/localStorage disclosure** — the game uses `localStorage` (`neon_*`
      keys) and Vercel Speed Insights; note it in the policy (no third-party ad cookies today).

**Acceptance:** both pages live and linked; Play console Data Safety completed;
a real "how do I delete my account" answer exists.

## B. Brand & logo redesign — **P1**

### B.1 Where we are

The current mark is a **generic ring-and-dot**: a dark rounded tile with a pink
ring (`#ff5fa2`) and a teal core (`#54e6b5`). It appears as:

- the **inline-SVG favicon** in `index.html` (`<link rel="icon" ...>`),
- the **PWA icons** (`icons/icon-192.png`, `icon-512.png`, + `-maskable` variants),
- the **Android launcher icons** (generated by `tools/gen-android-icons.cjs`, which
  explicitly "mirrors the favicon: dark tile, pink ring, teal core"),
- and the on-screen title is **CSS text** ("NEON / SURVIVOR"), not a designed wordmark.

There is **no logomark with personality, no wordmark lockup, and no social/share
image.** For an official launch the brand should read as a real product, be
recognizable at 16 px (favicon) and on a phone home screen, and look intentional
when a link is shared.

### B.2 Design direction

Goal: a **distinctive, neon-arcade mark** that survives from 16 px to a 512 px app
icon and a 1200×630 share card, in both light and dark contexts.

- **Keep the equity**: the neon palette (`#0a0a12` bg, `#54e6b5` teal, `#ff5fa2`
  pink, `#9b6dff` violet, `#ffd95e` amber) and the "survivor in a swarm" fantasy.
- **Concept options to explore** (pick one, don't ship three):
  1. **Monogram** — an "N/S" glyph fused into a targeting reticle or ship silhouette.
  2. **Ship-in-ring** — the player's core dot as the "eye," ring as an orbiting
     shield, with a subtle motion/energy cue — an evolution of today's mark, not a reset.
  3. **Wordmark-led** — a custom "NEON SURVIVOR" wordmark with a neon-tube treatment
     and a compact standalone logomark derived from the "N".
- **Wordmark**: choose/customize a geometric or arcade display face; define a
  stacked lockup (title screen) and a horizontal lockup (share card / README).
- **Constraints**: legible mono-color version (favicon, maskable safe-zone), a
  full-color version, and a knockout/mono version for the APK adaptive-icon
  foreground. Respect Android **maskable safe zone** (keep the mark within the
  inner 80%).

### B.3 Deliverables (mapped to real files)

| Asset | File(s) | Notes |
|-------|---------|-------|
| Master vector | `brand/logo.svg`, `brand/wordmark.svg` (new `brand/` dir) | Source of truth; everything else derives from these |
| Favicon | inline SVG in `index.html` (or `/favicon.svg` + `.ico` fallback) | Must read at 16–32 px |
| PWA icons | `icons/icon-192.png`, `icon-512.png` | `purpose: any` |
| Maskable icons | `icons/icon-192-maskable.png`, `icon-512-maskable.png` | Respect the safe zone |
| Apple touch icon | `icons/icon-192.png` (referenced) | iOS home-screen |
| Android launcher | regenerate via `tools/gen-android-icons.cjs` (update its draw routine to the new mark) | Adaptive fg/bg layers |
| **Social share image** | `og-image.png` (1200×630) — **new** | Currently missing; see §D |
| In-game title | replace CSS text with the wordmark (SVG) on `#start`, `#boot`, `#over` | Keep `NEON<br>SURVIVOR` fallback for no-image |
| Play feature graphic | `store/feature-graphic.png` (1024×500) | Play listing header |
| README banner | `README.md` top badge/hero | Uses the horizontal lockup |

### B.4 Workflow & gotchas

- Update `tools/gen-android-icons.cjs` so the CI-built APK icons match the new mark
  (it's zero-dependency PNG generation — the draw routine is what changes).
- **Cache busting**: `vercel.json` caches `icons/` (and `audio/`) for **30 days**.
  Per the repo's own gotcha, **rename changed asset files** (e.g. `icon-512.v2.png`)
  and update every reference, or returning players keep the stale icon. JS/CSS/HTML
  revalidate every visit, so `index.html` references update cleanly.
- Re-run `verify.cjs` after touching `index.html`; `og-image` and icons are static
  assets (no verifier), so eyeball them at target sizes.
- Provide **light + dark** favicon behavior if feasible (media-query SVG).

**Acceptance:** new mark renders crisp at 16/32/192/512 px and in the maskable safe
zone; wordmark on title screen; OG card shows the mark; APK launcher icon matches;
all old asset references updated (no stale-cache regressions).

## C. Store & distribution — **P1**

- [ ] **Stable Android signing key** — today the CI uses a *throwaway* key each build
      (per `README.md`), so updates won't install over each other. Generate a keystore
      once and add `ANDROID_KEYSTORE_BASE64` / `ANDROID_KEYSTORE_PASSWORD` /
      `ANDROID_KEY_PASSWORD` as repo secrets. **Required before the first public APK**
      you intend to update later.
- [ ] **Play Store listing** (if going to Play): title, short/long description,
      screenshots (reuse/refresh `audit-screens/` + `docs/reward-shots/`), feature
      graphic (§B.3), content rating (IARC), Data Safety (§A), target-API compliance.
- [ ] **Versioning** — adopt a tag scheme (`vMAJOR.MINOR.PATCH`); the APK workflow
      already keys releases off tags. Document the release cut in `README.md` (present).
- [ ] **Sideload path** — keep the direct-APK download working
      (`releases/latest/download/neon-survivor.apk`) for non-Play distribution.

**Acceptance:** a signed APK that updates in place; a complete Play listing OR a
deliberate "sideload-only" decision recorded.

## E. Backend hardening & live verification — **P0**

- [ ] **Confirm the leaderboard RLS lockdown in production.** `verify-supabase.cjs`
      is network-gated and could not run in the dev sandbox, so the anti-cheat
      boundary is *unproven from here*. Run it (or an equivalent) against production:
      an anonymous client `INSERT` into `leaderboard` **must be denied**, while the
      public `SELECT` still works. This is the whole point of the `/api/verify` cutover.
- [ ] **Rate-limit / abuse-guard `api/verify.js` and auth** — throttle score
      submissions and OTP requests (Supabase auth has some built-in limits; confirm
      and tune). Prevents board spam and email-bomb abuse.
- [ ] **Secrets hygiene** — confirm the `service_role` key lives only in Vercel env
      vars (never client), and the committed `anon` key is the intended public token
      (it is, by design — RLS is the boundary).
- [ ] **Backups** — enable Supabase point-in-time / scheduled backups for the
      `profiles` / leaderboard / achievements tables.
- [ ] **Error monitoring** — wire a lightweight client error reporter (or Vercel's)
      so launch-day breakage is visible.

**Acceptance:** documented proof that anon INSERT is denied in prod; rate limits in
place; backups on.

## F. QA & cross-device pass — **P1**

- [ ] **Device matrix**: desktop (Chrome/Firefox/Safari), iOS Safari, Android Chrome,
      the Android WebView (APK). Check touch joystick, pause button, zoom, RTL Hebrew.
- [ ] **Performance under load** — run `window.stressTest(1000)` on a mid-range phone;
      confirm the fps holds (pair with the F3 overlay).
- [ ] **Accessibility** — color-contrast on HUD text, focus order in the auth modal,
      `prefers-reduced-motion` for screen shake / flashes, ARIA on interactive controls.
- [ ] **Audio** — first-gesture unlock, tab-blur suspend/resume, genre switching,
      low-HP filter, boss overdrive; verify no stuck/duplicated loops.
- [ ] **Edge cases** — offline play → reconnect mid-run; sign-in on a second device;
      long callsigns / RTL names on the board; game-over → play-again loop.

**Acceptance:** a signed-off test matrix with no P0/P1 bugs open.

## Suggested sequencing

1. **Phase 1 — Identity (B, D):** finalize the logo/brand, generate every asset,
   wire OG/Twitter + SEO meta. This is the visible face of launch and unblocks the
   store listing and announcement.
2. **Phase 2 — Compliance & backend (A, E):** privacy policy + terms + deletion
   path; confirm RLS in prod, add rate limits and backups. These are the true P0s.
3. **Phase 3 — Distribution (C):** stable APK key, Play listing with the Phase-1
   assets and Phase-2 Data Safety.
4. **Phase 4 — Hardening (F, G, H):** cross-device QA, analytics, rollback + launch
   comms. Then flip the switch.
